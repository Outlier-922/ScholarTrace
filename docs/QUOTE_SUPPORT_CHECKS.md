# 陈述与所附引文核验

应用0.13.0。此功能针对“引文存在，但不能支持整句话”的问题。它是独立的一次模型复查，不是独立人员的事实认证，也不是已验证准确率的本地NLI模型。

## 操作

1. 在“引用图谱 → 自动综述与方向核对”生成草稿，或从历史打开既有综述/方向核对记录。
2. 点击“核验陈述与所附引文”。一次最多检查8条陈述，最多一次模型请求、2400输出token预留；模型只收到陈述、类型及实际附带的短引文，不收到整篇论文、隐藏段落、标题或标准答案。
3. 界面优先显示“模型建议引文支持的陈述”；展开“待修订原陈述”查看部分支持、矛盾或证据不足项，以及缺乏支持的原句片段和理由。所有原句均保留，不自动删改。
4. 展开“原始草稿与原模型建议”仍可完整查看原生成记录。原有论文覆盖只描述原始候选陈述，不是筛选后的事实覆盖或准确率。
5. 核对引文按钮可返回原PDF。检查前后文，尤其是指代、省略、否定、比较条件和因果。核验不完整时应修订原稿或补充证据，不能直接把“模型建议支持”当成已确认事实。
6. “导出核验建议与待修订原句”分别列出建议支持和待修订原句，并保留引文与解析锚点。原草稿导出仍导出原稿；研究任务ZIP里的review.md也仍是原始草稿，不会被单独核验悄悄替换。

核验不是生成草稿的自动隐含步骤，避免在用户不知情时增加请求。在同一原记录最近20条核验中，匹配原摘要、当前模型配置身份和提示版本时复用结果，重复点击不会再生成；单worker相同并发请求在成功保存后复用同一结果。配置或服务失败不缓存，等待请求可能再次尝试并计费。当前生产入口限定单worker，不承诺多进程或多主机间请求合并。改变模型配置/核验版本会产生新记录，旧记录不覆盖；界面显示最近一次已保存记录的时间和核验版本。

## 判定及失败边界

核验提示要求逐分句检查数值、条件、比较对象、因果与否定，返回supported、partial、contradicted、insufficient四类。模型必须给出理由和从实际所附短引文中逐字摘取的依据；部分支持或矛盾还要定位到原陈述中的连续子串。完整支持需涉及全部所附引文；完整支持却又报告缺乏支持片段时，服务端降为部分支持。

重复/缺失ID、未知状态、伪造引文、跨文漏引、无效原句片段或空理由，不会成为支持建议。输出不合法时该条显示“证据或核验输出不足”。未配置模型、服务失败和预算不足时显示未完成，不保存伪造通过记录；原草稿继续可查。请求中止不能保证服务商取消计费。

原记录通过内容摘要绑定，核验同样保存文件SHA256、ParseRun、证据块与坐标；保存前再次检查来源。删除来源使原记录及核验不可用，重新解析仍保留旧锚点。核验历史GET不会发起模型请求，受控只读演示不能新建核验。任务的模型计量上下文和演示小时额度都由同一个模型适配器执行。

这些工程检查只能验证输出形状和文字对应，不能证明模型判定正确。核验可能与生成使用同一服务/模型，二者错误相关；未额外配置独立模型。所有结果仍为semantic_verified=false，不计算或显示未经校准的可信概率。

## 已知限制

本轮对上轮真实草稿和两篇新论文进行小规模检查，保留正负结果，具体见STAGE16_TEST_REPORT.md。仅比较实际短引文可能比阅读完整段落更保守，也可能因模型补入背景知识而误放行；旧BERT样本中前文被截断的引文就是已发现的边界。

当前不自动改写、补引文、补检索或确认方向已解决，也没有全领域完整性保证。问答、比较矩阵、翻译及写作模板尚未全面接入该核验；本功能的通过条数不能代表整个产品质量。正式交付仍以ACCEPTANCE.md的必要缺口为准。
