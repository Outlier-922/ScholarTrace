# 第七阶段：研究任务与真实模型接入

更新：2026-10-28。版本：0.7.0。开发验收跨 2026-10-27—28；本机单用户版本。

## 已实现

- 新增“研究任务”：输入意图、选择文献，先展示步骤再执行。支持规则规划与可选模型建议，模型只能从五个已实现工具中选择，不能添加任意命令、下载或删除。
- 将原文检索、多文对比、引用图谱、写作框架和流程图串成持久化任务。选定文件、SHA-256 与 ParseRun 后，后续重新解析不会让旧任务的来源漂移。
- 记录步骤依赖、状态、尝试次数、来源、产物、事件与预算。支持步骤边界暂停、取消、预算耗尽后继续和服务重启恢复。
- 已完成步骤保留检查点；图谱、比较、写作与图像使用确定产物 ID，处理中断后可复用已经写出的产物。
- 部分文献未命中时最多增加一次补检索，仍占工具预算；未支持的翻译、联网发现、CSV 规则等明确列为未完成项。
- 新增隐藏输入密钥的本机配置向导、“配置模型.cmd”“启动科研助手.cmd”和连接状态界面。配置原子写入本机 .env，保留其他设置，不保留临时密钥副本。
- 固定小请求检查模型连接，区分缺少配置、连接成功和质量未验证；服务商错误正文不返回浏览器。轮换密钥后不复用旧连接成功记录。
- OpenAI 官方端点默认使用 max_completion_tokens 并省略固定 temperature；兼容接口沿用 max_tokens。可通过 LLM_API_PROFILE 显式选择，型号仍由用户账号配置。

本阶段采用 **SQLite 状态机的受控编排**，尚未实现设计方案中完整的 LangGraph Supervisor、多角色自主协商或通用重规划。界面的角色名称表示工具职责，不代表多个独立模型代理。本阶段没有开放自由代码执行。

## 预算口径

工具调用数、执行模型请求数、输出 token 预留和活动时间分别记录。每次执行模型请求发出前占用请求数与输出额度；失败请求也保留预留，并将未取得的实际用量标记未知。

时间与暂停/取消在步骤边界检查，不会抢占已经发出的模型请求。服务突然退出时，中断请求可能已经计费，恢复也不能保证外部请求只执行一次。规划另有最多一次模型请求，连接检查和独立问答/翻译不计入任务执行预算；当前记录不能冒充账号总费用或硬实时限制。当前只支持单 API 进程。

## 自动验证与构建

在第六阶段 142 项检查上新增 21 项，覆盖：

- 受控计划、真实产物与 ZIP、无模型执行、恶意工具建议拒绝。
- 工具/模型预算、部分结果、一次补检索、暂停/取消、确定 ID 复用。
- 重新解析后固定旧来源、删除后失效、SQLite 恢复与关闭服务时排队任务不重启。
- 本机配置原子写入、旧设置保留、无临时副本、脱敏错误、密钥轮换后的连接状态。
- OpenAI 参数适配、调用前预算预留、事实检索正文优先、训练阶段线索、书目续行排除及附录/新章保留。

最终完整结果为 163 passed, 1 warning in 20.32s，记录在本机 data/stage7_verification/tests-final.txt。新增模块单独复验为 21 passed；TypeScript 与 Vite 生产构建通过（1596 modules）。测试模型均是注入响应及虚构密钥，真实模型验收另列。

## 真实 DeepSeek 检查

用户在本机配置 DeepSeek 后，固定小请求连接成功，端点 api.deepseek.com，型号 deepseek-flash。没有把密钥送入聊天、浏览器或提交文件。

使用官方 Transformer v7、BERT、GPT-1、GAT v3 做本地任务；模型抽取小样本仅涉及 Transformer 与 BERT，不发送整本文献库。

| 检查 | 结果与限制 |
|---|---|
| 无模型任务 | 4 个来源，5 步，12 个初始候选锚点；先到工具预算，再继续完成 |
| 真实模型规划 | 返回受工具白名单约束的 4 步计划 |
| 真实模型执行 | 3 次执行请求；原文回答、逐文硬件/优化器提取、图谱和研究计划产物保存 |
| GPU 事实题 | 找到 8/P100 的来源；回答带有额外训练条件，仍需检查相关性 |
| BERT 批量与最大长度题 | 初次漏检 256 sequences；修复后恢复该字段，但最大长度仍被模型保守列为缺失，判为部分回答 |
| 未报告显存题 | 未保留事实陈述，没有从 P100 型号补造显存容量；缺失说明限于所给证据 |
| 对比条件 | 保留 BERTBASE / BERTLARGE 的 TPU 条件；优化器区分预训练与微调候选 |
| 单段翻译 | 首次真实翻译完成，复验命中缓存；人工核对八个 P100 GPU、十二小时及“摒弃循环” |

修正后的模型任务 12459d95-81c5-47bd-815f-17cc1e61b783，执行侧服务商报告输入 2729、输出 1397 token，输出预留 6600。此用量只包含该任务的三次执行请求，不含规划、连接检查、独立题目与翻译，不据此估算总费用。

这只是开发小样本，曾用于定位并修复问题，**不是独立测试集，不报告“准确率100%”**。来源 ID 与数字检查不等于语义蕴含；自动报告的关键词出现也不等于问题完整回答。

## 实测问题与修复

1. BERT 的 256 sequences 原文已被解析为原生 table_candidate，初次未进入前六候选；短标题挤占了证据名额。增加正文优先级与显式阶段线索排序，不写死论文名或答案。附录正文保留，误分类候选仍可检索。
2. 优化器查询先命中微调参数。调整通用查询词，加入 warmup、weight decay 等设置；把问题目标传入逐文抽取，要求保留阶段和模型规模，不把不同条件混为一个值。
3. 书目中的年份行有时被误判成标题，导致普通节路径不能可靠排除续行。补充 References 到附录/新章的区间约束，保留新章可检索性。
4. 模型未通过校验的比较单元格保留候选及具体拒绝状态；界面明确显示“原文匹配候选”或“来源数字检查通过，语义待核验”。
5. 任务完成后历史下拉曾停留在“执行中”，补充终态刷新。服务关闭时停止排队回调重新调度，等待任务留待恢复。

首次报告保留在 data/stage7_verification/，修正后报告在 revised/；最终 BERT 复验另存 final-bert-qa.json，不覆盖首次失败记录。

## 浏览器与重启验收

浏览器创建任务 1ef28155-9039-4593-8ce7-51e3cf8eec52，将工具上限设为 1。第 1 步后达到预算，保存检查点；停止并重启 API 后仍可打开同一任务，将上限改为 8，继续到 5/5。

重启前后的第 1 步结果逐项相同，尝试次数仍为 1。总工具调用 5，执行模型调用 0。恢复结果导出为 restart-task.zip；这项实际重启检查验证预算暂停后的恢复。执行中断后的产物复用与排队关闭另由自动测试验证，不混淆两者。

桌面 1440×1050 与窄屏 390×844 验证。窄屏内容宽度 374、视口 390，无横向溢出；模型对比的“原文 p13”回到 BERT PDF 第13页。浏览器无 warning/error。
