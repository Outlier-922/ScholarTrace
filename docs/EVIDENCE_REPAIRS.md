# 补充原文、生成修订稿与重新核验

功能自0.14.0接入，当前应用0.25.7。此功能在“陈述与所附引文核验”之后，帮助查找不完整引文的上下文并修订草稿。它不会把补到段落、格式校验通过或模型支持建议当作事实认证。

## 操作步骤

1. 打开“引用图谱 → 自动综述与方向核对”，选择已保存的综述或方向核对记录，完成或读取引文支持核验。
2. 在“补充原文与修订”选择1—3条陈述。默认选择至多3条未获完整支持建议的陈述；已经获得支持建议但引文截断的陈述，也可手动勾选。
3. 点击“查找补充原文（不调用模型）”。系统在这些陈述原先引用的论文及原ParseRun中查找候选，不访问外网，不从整个库随意换论文。展开候选并点击页码检查原PDF，可导出候选预览。
4. 点击“按候选原文生成修订稿”。每次新生成最多一次模型请求，预留2400输出token；不是实际账单用量。修订稿只包含本次所选陈述，未选内容继续留在原稿。模型应缩小没有支持的断言；无法形成有效修订时保留“未形成可保留修订”。
5. 查看“修订前后对照”，再点击“打开修订稿，重新核验”。这会打开一条新记录，尚未产生语义通过结论。另点“核验陈述与所附引文”才进行一次独立操作的模型复查，最多另一次请求、2400输出预留。
6. 原稿、旧核验、候选预览、首次失败和修订稿均保留。历史重载与导出不自动生成；修订稿也可从综述历史找到。修订导出包含原记录摘要、原句、修订、理由、引文处理及原文锚点。

“独立操作”仅指另一次请求，不表示独立模型或独立人员。生成和复查可能来自同一模型，仍会重复错误。研究任务ZIP中的原review.md不会被此操作悄悄替换，当前也没有把该流程自动接入所有问答、比较、翻译或任务步骤。

从0.25.7起，修订输入同时包含所选陈述的核验状态、理由、缺乏支持的原句片段、范围判断及字面范围提醒。它们来自被绑定的核验记录，不由界面任意改写，也不混入未选陈述的意见。旧核验没有的新字段按缺省处理。意见只是待复核线索，事实依据仍只来自该陈述允许的原文窗口；不能把模型理由当作补充证据。

本次真实核验仍漏判了一条范围问题；修订请求返回502且没有新稿，预览和旧记录保留，没有自动重试。反馈传递的软件回归已验证，这次实测不能证明修订质量提高。首次结果见[阶段41](STAGE41_TEST_REPORT.md)。

## 原文范围与引文处理

每条陈述仅使用它原先引用的文献，版本固定到旧ParseRun；重新解析后不漂移到新版本。每篇针对该陈述做一次本地检索，取至多2个命中，再加入原块上下文和有限相邻候选。一次最多12次本地查询，每条最多8个候选窗口、共最多24个，窗口最多1600字符。检索范围有界，不声称穷尽全文或领域。

长块窗口尽量覆盖原短引文附近文字。各窗口保留原块文字、页码和坐标；引用范围相对模型文本表示，不是PDF词级坐标。部分上标沿用绑定原文哈希的版式文本表示，仍应检查原图。相邻块和跨页候选各自保留锚点，不拼成一段虚假的连续引文。

对于上一页末尾英文断词与当前块开头片段，只有两部分能组成原陈述或引文中实际出现的词时，才列入有限候选。若存在唯一候选，可把上一页原文作为另一条引文补入；有歧义时不自动加入。词形对应不保证阅读顺序或语义连续，特别是双栏、页眉、脚注与OCR，仍需对照原页。

模型若对同一证据输出多个短引文，可以扩为同一原文窗口中的真实连续范围，包含其间原有文字；合并范围超过300字符时不保留，不能用省略号拼接。跨页前后片段始终是两条独立引文。模型请求的未知证据ID不会被修复操作清除或洗成有效来源。

## 不再生成的响应重新校验

已经保存修订响应时，可点击“重新校验已保存响应的引文（不调用模型）”。它复用同一核验记录、同一组陈述的完整原响应，只按当前候选范围处理连续引文及唯一跨页断词候选，然后重做来源、类型、数字与短引文检查；不会请求服务商或改写原模型文本。

这适合输出格式或原文候选处理改善后的回放。原响应和首次结果不覆盖，新记录注明响应来源；不能拿别的陈述组响应来替换。没有模型密钥也可执行此本地步骤，但之后的新语义核验仍需要模型。相同预览、模型身份、提示与校验版本匹配时复用已保存结果；查询历史只检查最近20条。单worker成功结果可供等待请求复用，失败不缓存，多worker合并尚未实现。

## 失败和当前局限

未知或重复陈述、外部证据、跨陈述换来源、类型不符、数字或短引文无效，都不能偷偷退回旧句并冒称修订成功。预算/配置/服务错误保留预览并显示失败。来源删除后预览、修订和核验失效；生成期间再次检查来源。中止界面请求不能保证服务商不计费。

如果修订的是未来工作核对理由，新理由不会自动把方向升级为“已解决”；结果先回到保留待查、关系不足，需另行核对解决程度。

模型仍可能新增原句没有的事实、误判局限、错分章节或把理由归到错误的引文。所有结果保持semantic_verified=false。真实Transformer/BERT开发回归、首次失败和已知问题见STAGE17_TEST_REPORT.md；必要交付缺口仍以ACCEPTANCE.md为准。
