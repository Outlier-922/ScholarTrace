## 代码与边界

DemoGuard为纯ASGI中间件，保护根页面、静态资源、API、PDF、Swagger和OpenAPI。认证为单账号HTTP Basic，向导保存PBKDF2-SHA256、600000轮及随机16字节盐的哈希；不记录真实密码。成功认证头仅在进程中缓存摘要以避免每个静态资源重复执行慢哈希，变更配置需重启。

仅`/healthz`允许未认证的最小健康信息。域名必须符合指定Origin；跨站Origin/Fetch-Site被拒绝，写请求需要同源Origin或显式API客户端头。演示模式不开放跨域CORS。设置no-store、nosniff、DENY及no-referrer。不是外部安全审计或完整攻击防御证明。

默认只读，阻止HTTP写方法，暂停自动追踪和翻译/任务/解析恢复；初始化仍可维护表结构及中断状态。交互时有请求滑动窗口、认证失败窗口、总body大小和HTTP写入并发限制；后台任务、磁盘总量及上传数仍需进一步配额。模型请求尝试/输出预留按UTC整点小时记录SQLite，各工具共用，重启不清零；不是完整输入token或计费账单。

独立启动器加载私有.env.demo、固定127.0.0.1和单worker、不信任转发头、禁止默认开发data目录，并取得独占文件锁。只挂载apps/web/dist，不挂载仓库或数据目录。向导默认独立数据目录、只读、0模型额度，显式空LLM配置避免继承开发密钥。

## 浏览器验收

已登录后使用干净本机地址，能加载一篇2页合成文献、30个内容块，PDF画布和原文可见；只读共享提示明确，导入与发送按钮禁用。其他工具的写操作仍由后端拒绝并展示错误，不宣称所有操作控件均在前端隐藏。

自动化首次用含虚构测试凭据的URL建立HTTP认证时，浏览器拒绝相对fetch，出现“带凭据URL不能构造Request”。随后导航干净URL，认证缓存生效，API及PDF正常；这不是修改产品隐藏失败，指南明确禁止实际用户把密码拼入URL。没有以此测试真实凭据或把URL凭据方式作为登录建议。未自动操作浏览器原生账号弹框。
