# 字段核对使用说明（0.9.0）

在“文献与阅读”勾选所需论文，在右侧循证助手提出明确问题。跨文提问时写出模型条件，例如：“分别比较 DistilBERT 和 CLIP 的 RN50x64 训练GPU数量、型号与耗时，保留具体模型条件，不据此给效率排名。”请自行核对所选文献和版本。

回答按论文及版本分组。“已识别字段的覆盖”列出本次识别到的字段；点击每项“原文”跳到它的第一条候选来源，其他引用仍可通过回答和证据列表查看。计数表示通过结构检查的候选字段数，不能解释为回答正确率或问题完整率。请同时查看是否遗漏了问题的一部分。

| 状态 | 含义与处理 |
|---|---|
| 有候选回答 | 有保留陈述及同篇有效来源；继续检查事实、条件与单位 |
| 候选证据不足 | 模型标记给定候选证据不足；不能推断全文未报告，可缩小问题或增加检索 |
| 本次未完成 | 未生成该字段，或该文未进入模型上下文；可拆题重问 |
| 冲突或检查未通过 | 字段输出冲突、同字段多种答案或来源/结构检查未通过；保留的候选也需复核 |
| 来源已失效 | 来源删除后标记失效；相关陈述不再作为有效答案展示 |

当前识别硬件数量/型号/显存/时钟/电压、耗时、语料、数据规模、查询数、训练目标、部件变化、层数/结构、词表大小/分词/共享、批量、序列长度、步数/轮数、优化器和公式等固定类别。未知表达、多重否定、混合问题可能识别不全。一次最多处理8类字段，复杂问题请拆开；“不要只比较……”保留为正向需求，“不从型号推断”等独立限制子句不增加字段，但规则不能覆盖所有自然语言。

先执行通用检索，再按论文和已识别字段补查，最多12次本地查询；候选结果仍受请求k上限约束（最多12）。达到预算或字段上限会提示。补查不增加大模型调用次数；普通问答仍至多一次生成、输出预留1600 token。未配置模型时只返回证据，不生成覆盖答案。

模型字段行最多20条；必须对应已选论文和所问字段，引用不得借用其他论文。数字、来源与明显公式残片会被检查。系统没有完整语义蕴含或数学正确性验证；文字数字一致也可能误读条件。不要据此自动推断未报告的GPU电压/时钟，也不要仅以GPU数量和天数给效率排名。

本轮示例来自已观察开发题。DistilBERT层数仍有待核对状态，H01指定证据组仍漏召回。CLIP有一页表格提取超预算，文献保持partial，正文可用；不能把此状态视为所有表格已解析。旧解析快照及历史原文锚点继续保留。
