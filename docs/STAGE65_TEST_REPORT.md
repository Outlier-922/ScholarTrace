# 跨页续句整体翻译与双页来源映射

日期：2026-11-15。

## 参考方案与设计决定

先查官方项目文档和原始论文，再修改实现：

- [Docling 的结构化分块](https://docling-project.github.io/docling/concepts/chunking/)将文本和来源元数据一起组织，并在文档结构之上处理长度限制。借鉴其“语义处理单元不等于原始版面块”的组织原则；没有引入Docling依赖，也不声称直接使用其算法。
- [BabelDOC论文](https://arxiv.org/abs/2605.10845)将语义内容和版面信息分离，翻译后再关联布局。
- [BabelDOC issue 576](https://github.com/funstory-ai/BabelDOC/issues/576)报告逐页切片独立翻译导致跨页截断，提出先识别和合并段落。该问题报告是设计参考，不是上游已解决或正确率保证。

本地实现使用原生文本、明确未完语法、相邻页、接近页尾/页首与相似横向边界识别两段续句。只合并用户已选范围内的两块，不跨文献、解析版本，不自动处理OCR，不跨明确编号新章节，不超过12000字符。默认启用，可在新计划中关闭。所有规则不包含论文名称、块ID或预期翻译。

## 数据与执行变化

计划保留两块原文及各自指纹：主段保存联合翻译，续段标为linked并指向主段。manifest摘要包含组合关系。缓存键绑定联合文本与新的translation-v5-semantic-groups版本，不复用旧的单块译文。

主段一次模型请求处理连续原文；每个成员在执行前后检查原文指纹。预算按翻译单元计费：一组两块仍为一次请求、3500输出token上限；界面分别显示译文单元和并入块数。续段本身不伪装成已翻译，主段未完成时任务也不能完成。续页按ID读取主段，避免每次加载整篇清单。

页面展示完整译文与两个原文跳转按钮；续页返回主段。JSON保留group_sources/translation_sources，HTML/Markdown明确标识续段关系。原PDF、源块、旧计划和旧校订不改写。联合译文不再强拆成两个中文残句，不宣称逐字跨页对齐。

## 真实验证

共2次真实模型请求，总预留7000输出token；各题仅首次运行一次，没有为挑选较好结果重试，未对本轮结果手工校订。

1. **原已知失败：DistilBERT第3—4页。** 两段合并后一次生成，正确表达先前微调的BERT作为教师，为损失增加附加项；预训练/适配两阶段、79.8 F1、70.4 EM和相差3分以内均保留。不再出现“教师项”或前后两段重复教师关系。结果仍含“有趣的性能”等直译措辞，不把事实关系改善等同于文风完美。
2. **另一来源：GPT-3第33—34页。** 续接“limits of the pretraining objective”，译文保留may/could/likely/might的不确定性、目标权重、经验接地限制及未来方向，未扩写为确定结论。属于开发助手原文对照，不是独立盲测。
3. **缓存：** DistilBERT新计划重放，1个cached主段加1个linked续段，零新请求。
4. **页面：** 从第4页续段跳到第3页连贯译文，点击第4页原文定位并高亮，再返回主段，均通过；零新模型请求。
5. **自动化：** 完整回归838项通过（192.30秒，1项已有Starlette/httpx弃用提示）。随后续页主段查询改为按ID读取，相关32项复测通过。TypeScript和Vite构建通过。

## 边界与完成状态

原已知跨页语法关系失败已按上述场景修复。M3-PARALLEL仍有更广的全文质量、复杂版式及对齐验收，不能仅凭两题整体标为完成。当前识别限两页原生英文、有明确语法线索和版面约束的续段；三页以上、OCR、跨栏、断词连接和一般语义连续段落暂不自动合并，继续使用原有逐段路径和核对提示。
