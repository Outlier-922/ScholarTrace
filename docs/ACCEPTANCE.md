# 到什么程度才算完成

状态：当前为0.41.0；本轮只验收作品功能，展示发布事项由用户后续处理。日期为 2026-11-14。

此前阶段报告中的“完成”只表示该阶段工作结束。版本号、测试数量和证据组召回都不能换算成作品完成百分比。

明确的四个完成关口、固定收尾工作包与本人参与事项见[交付收尾计划](DELIVERY_PLAN.md)。六模块已有入口不等于必要能力全部完成；后续按清单关闭缺口，不再以新增阶段数作为进度依据。

## 产品完成条件

1. 功能：下面赛题必要项都实现并按承诺范围实测；部分实现和未实现项不得标记已通过。非指定框架、额外性能优化不擅自升级为主办方要求。
2. 验证：官方版本去重、扫描件、541页长书、问答溯源、多文比较、翻译、发现、图谱与写作绘图各有可复查的运行记录；错误和局限清楚标记。模型答案应按原文核对，不能以ID有效代替事实正确。
3. 展示、仓库上传、最终PDF、视频、公网与身份信息由用户后续处理，不计入产品完成条件。见[范围约定](PRODUCT_SCOPE.md)。

独立人工质量复核、完整备份恢复和生产隔离是建议的工程验收工作，其中“独立复核”不是从提供规则中引用的额外强制条款。公开演示可使用明确限定的共享素材，但不得描述成已有多用户隔离。

近期问答修复：LayerNorm位置、稳定性和warmup分别检索，保留理论与实验范围；详见[实测记录](STAGE62_TEST_REPORT.md)。组件存在性判断已单独覆盖，明确否定需原文摘录，见[组件判断实测](STAGE63_TEST_REPORT.md)。这些开发案例不替代完整问答质量验收。

## 收尾顺序

A. 补功能缺口：选区翻译及自动综述/方向核对已接通，但真实样本质量未通过；继续补语义支持检查、检索完整性、公式/图表和意图流程覆盖，避免只追加阶段文档。
B. 集中验收：完成官方样例整链路、事实/译文核对和新作品验证；以真实记录更新表格。未通过的字段保持未通过。
C. 产品复核：继续按官方代表性问题检查语义、条件与功能，展示发布由用户后续处理。
D. 功能冻结：关键功能缺失与已知错误关闭后，交由用户准备展示发布，不因材料尚未制作否定产品完成。

机器状态在evaluation/acceptance.json。默认运行scripts/check_acceptance.py只检查产品功能；--require-ready也只针对产品。需要单独检查官方提交材料时显式指定--scope submission。

当前开发不等待服务器、账号或展示材料；这些由用户后续处理。
