# 第十六阶段：陈述与所附引文的支持核验

日期：2026-10-29（北京时间），应用0.13.0。新增一次有界的模型复查与待修订区，处理阶段15已观察到的“引用真实，但陈述超出引文”问题。整体正式交付仍未完成，自动综述质量没有被改记为通过。

## 实现与边界

claim_checks.py从已保存综述或方向核对记录抽取最多8条陈述，给复查模型的输入只含陈述ID、原句、单文/跨文类型及实际所附短引文，不给标题、隐藏上下文或答案。模型须逐分句检查数值、条件、比较、因果与否定，返回supported、partial、contradicted或insufficient、理由、缺乏支持的原句子串和所用引文子串。

服务端核对输出ID、唯一性、状态、原句和引文子串、跨文引用完整性；supported同时报告不支持片段会降为partial。畸形、遗漏、重复或伪造引文输出归insufficient，不变成通过。模型配置/服务/预算错误保留为未完成，不保存虚构核验。原记录的内容摘要、来源SHA256、ParseRun和块坐标同时绑定；源删除失效，重新解析仍指向旧锚点。

核验单独保存，原草稿不覆盖。页面优先显示模型建议支持的陈述，其他原句折叠于“待修订原陈述”，带理由和高亮原句片段；原始草稿仍可展开。按真正的单文/跨文类型展示标签，不把旧栏目标题当跨文证明。导出分开列支持建议和待修订原句，并保留引文与解析锚点。研究任务ZIP仍导出原稿；本轮没有把检查自动接入所有任务、问答、翻译或比较。

在同一原记录最近20条内匹配原摘要、模型配置身份和提示版本时复用记录；单worker相同并发请求在成功保存后复用，失败不缓存，等待者仍可能再次尝试。只读可读历史不能新建。每次新的核验至多1次请求、2400输出预留token，仍走既有模型适配器的任务计量上下文及演示小时额度。不声称多worker分布式请求合并。

这只是模型二次判断，可以与原生成使用同一模型，错误相关。所有记录仍semantic_verified=false，没有独立人工认证、校准置信度或质量通过率。

旧样本的支持建议仍有已知漏洞：BERT引文从“former is often referred to...”开始，前面的词语/限定被截断，短引文本身未给出“双向版本”限定；复查却称引文明确说明双向版本，可能补入背景常识。因此不能宣称复查已消除幻觉。新样本中Post-LN核验虽然拦住预热效果分句，理由又把所附引文未给出的初始化条件称为已支持；核验理由本身也需核对。

新样本将LoRA的单文数字结果归入“跨文综合”，kind实际上为paper_fact。观察后补服务端守卫：comparison栏目必须是跨文synthesis且满足既有双文来源条件；新增合成回归检查，未对真实新样本重新生成。调用前指纹保留原状态，最终指纹另外记录；不能拿最终分类守卫冒称已用于那次首次生成。界面历史读取还补充中止/迟到响应检查。

三个真实请求后停止生成，另一次旧记录“复用”点击返回同一核验ID；历史读取、重载、导出和定位均不生成。实际账单token未知，7200只是预留输出上限。保存的stage16-check-observed.json、stage16-review-fresh.json、stage16-check-fresh.json保留原句、短引文、核验理由和来源指纹，不用手工改好的内容覆盖模型响应。被拒绝的完整生成提案未留存，不能逐项断言3项拒绝原因。
