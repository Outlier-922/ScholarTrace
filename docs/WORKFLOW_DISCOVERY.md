# 研究任务中的文献发现（0.21.0）

研究任务现在可按明确的检索词、来源、方式、作者和年份执行书目查询，保存筛选理由、未采用候选与检索快照，并直接打开已有“发现与追踪”核对页。该步骤取得书目元数据；全文核对入库沿用独立入口，旧任务的原文来源保持固定。

## 从页面使用

1. 打开“研究任务”，输入“查找相关论文”等发现意图，或手动勾选“文献发现”。同时选择已有本地文献作为当前任务上下文。
2. 在“明确要找什么”中填写检索词、标题或DOI/arXiv标识符。来源可选arXiv、Crossref或两者；方式为标题、主题或参考文献。
3. 选择每来源候选上限1—5条。可填作者字面包含条件与严格年份；不匹配或缺失字段的候选保存在“未采用候选”。反馈中的已点踩项沿用原有隐藏规则。
4. 联网方式默认“仅读本地缓存（可含过期快照）”。需要查询官方服务时，明确选“允许按以上条件联网检索”。大模型开关与书目联网独立。
5. 生成计划，检查“确认书目检索条件”及“书目联网请求上限”，再开始。精确标识符会自动选择对应注册服务，不对两个服务重复查询同一DOI。
6. 查看候选的注册来源、作者、年份、身份核对结果及筛选理由；缓存和过期时间状态单独标明。没有缓存或请求失败会保留具体状态，不等同于论文不存在。
7. 点击“打开此检索快照核对与入库”。核对页读取已保存的本地快照，不自动重发查询；可继续核对身份与版本，按原有入口确认具体arXiv版本PDF入库。Crossref元数据通常仅提供出版方全文核对链接。

确认全文已入库后，再选这份文献创建后续任务。旧任务不自动扩大来源，也不把候选摘要加入原文问答、图谱结论或写作证据。独立核对页的手动“检索”属于新的操作，沿用其原有候选显示与作者/年份提示规则，不受旧任务限额约束。

## 预算与反馈

每个注册来源独立一步。书目请求上限0—4次，默认2次；在实际发出HTTP请求前保存预留，缓存不占联网次数。只读缓存的执行路径还在请求边界阻止联网。请求失败仍计尝试次数，没有自动重试。

预算不足时当前步骤保持待执行，可显式调整预算后恢复；已完成来源不重新查询。暂停/取消沿用步骤边界，正在执行的请求可能需要结束后才生效。

已捕获的服务失败或限流，按“保留原文并转本地流程”策略和剩余调整次数，保留原失败快照、插入本地书目读取步骤并重接依赖。此后本任务的其他发现步骤也只读缓存；不扩大联网权限或预算。过期缓存会明确标记，未重新联网，不能据此声称“最新”。停止策略、次数耗尽或未知工具错误仍停止。

任务包新增`discovery/步骤ID.json`与Markdown，保留原条件、候选、未采用原因、服务状态、缓存时间和原注册URL。失败原尝试还保存在`task.json`与计划历史中。
