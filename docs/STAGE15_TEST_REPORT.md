## 实现范围

新增insights.py与insight_store.py，图谱页面加入“自动综述与方向核对”。综述一次1—8篇，每篇最多4个片段，每片最多1400字符，输出最多8条；未来工作一次最多3篇已入库候选。元数据不能替代全文，同作品版本不能充当后续独立研究。

每条陈述核对来源归属、数字与短引文。为PDF空白、兼容字形和英文行末断词加入可逆匹配，保存反向定位到的原文。没有引入通用拼写纠错或数字模糊匹配。结果固定到文件哈希、ParseRun、块、页码与坐标，重新解析不漂移，删除失效。原文匹配不等于语义蕴含，所有生成仍标记未语义核验。

未来核对使用双边全文片段和确切arXiv版本日期约束，仅给出可展开的模型建议分组；未知日期、同日、较早、部分涉及或检查失败均保留。不会删除原方向，也不把保留项当作创新点。研究任务增加第六种review工具，共享模型预算、确定产物ID、恢复与ZIP导出；无模型/预算不足降级原文提纲。

v1失败后，检查发现证据分配没有为每篇保留摘要，且PDF换行/兼容字形使模型短引文难以逐字匹配。因此补充摘要候选和可逆匹配，并新增相关单元检查后进行一次有实质改动的重试。未保存被拒绝的完整模型提案，无法逐项追溯7条拒绝原因，不能宣称它们全由换行造成。v1永久保留，没有用v2覆盖。

v2的明显问题：BERT局限一条在“随机掩码并预测原id”的引文之外加入“训练与微调不一致、原文未进一步讨论”的判断；所附引文不足以支持后半句，服务端现有检查未能拦住。第一条Transformer陈述的译文质量/并行性部分也超出所附短引文，需看更完整原段。此处为开发者检查发现的问题，不是独立人工裁决或质量准确率；不能把“两篇均有引用”报告为“两篇总结正确”。

总计本轮 **3次真实生成请求**：两次综述各2400、一次方向核对1800，输出预留上限合计6600token，实际账单用量未知。原计划两个功能各一次；v1失败后的通用修复增加一次综述重试。后续历史、跳转、导出与锚点检查均只读，没有继续挑选更好答案。
