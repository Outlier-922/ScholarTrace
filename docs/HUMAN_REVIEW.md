# 离线人工复核操作说明

当前产品0.9.0（b65058f），材料阶段12。已为阶段11六题生成本机页面：`data/stage12_review/review.html`。在项目根目录双击“打开人工复核.cmd”即可打开，主应用无需启动。页面包含论文片段，仅供本机复核，不放进公开仓库或材料包。

## 逐题操作

1. 核对题目、原始保留回答与缺失说明，再看“标准事实草稿”。草稿也可能错误，不能直接据此给分。
2. 点击陈述后的“查看 ev…”到对应候选片段，展开指定证据组和版式候选。根据文献版本、PDF页码、块坐标和ParseRun，在原PDF中确认上下文；片段可能截断，上标可能是脚注，不能只看数字。
3. 填写真实复核人、完整回答判定、标准事实核对状态和判定依据；确认已核对原文及完整回答。缺少必要信息会继续保存为待复核。标记“标准需修订”时在依据中写明修订，不直接改历史题集。
4. 有语义支持的陈述条数可留空。若填写，必须是0到该题陈述数的整数；它只描述已保留陈述的支持情况，不能证明漏项不存在。
5. 点击“导出复核 JSON”。页面不自动保存，关闭前必须导出。重开可“导入此前记录”，只接受同一套问题和响应哈希；不兼容旧CLI中缺少标准事实核对状态的记录时，保留旧记录并重新填写页面所需字段，不手工伪造哈希。

页面不联网、不调用模型，也不自动计算准确率。填写者自报身份和勾选不能证明独立性；真正独立复核需要未参与开发/标注的人按原文完成。当前六题仍全部待复核。

## 判定口径

| 判定 | 使用口径 |
|---|---|
| 完整正确 | 回答全部所问字段，保留模型/阶段条件、单位和约数，无实质额外错误或冲突缺失声明 |
| 部分正确 | 部分正确但有漏项、条件遗漏或其他实质问题；必须说明 |
| 错误 | 核心事实或结论错误；指出来源和错因 |
| 未保留事实 / 拒答 | 最终没有保留事实，不据此推断模型一定主动拒答；纯检索不是拒答质量样本 |
| 服务或运行错误 | 记录可复核的运行错误，避免把错误伪装成正确拒答 |

已有保留陈述时，页面禁用“未保留事实 / 拒答”；没有真实模型保留回答时，禁用完整/部分/错误三种答案质量判定。原CLI还有自己的来源、哈希和评分约束。不要只从“有候选回答”、ID有效或严格块命中推导质量。

## 生成离线报告

将下载的JSON复制到项目data目录，例如`data/my_reviews.json`，运行：

~~~powershell
.venv312/Scripts/python.exe -X utf8 scripts/review_evaluation.py --run data/stage11_live_v1/20261028T105135Z-d1bb35de --reviews data/my_reviews.json --output data/my_review_report.json
~~~

此命令读取原响应，不调用API，且拒绝覆盖已有输出。未全部复核时完整正确率保持null；支持条数未填完整时引用语义支持率仍为null。完整率条件只针对这次选定样本，不能推广为所有论文准确率。标准事实若需修订，应另建题集版本和说明，保留旧运行。

## 从其他原运行生成页面

~~~powershell
.venv312/Scripts/python.exe -X utf8 scripts/build_review_workbench.py --run data/某次评测/运行目录 --pack evaluation/对应题集.json --output data/新的复核页.html
~~~

生成器核对每题与原响应哈希，拒绝重复题、空运行、篡改输入和覆盖输出；不读取模型密钥。历史运行必须配其原题集，不能拿阶段11修改过的split字段去匹配旧题哈希。浏览器导出的记录只是JSON；分享前另行核对隐私、原文分发权限及复核人身份。
