# 研究任务：有界反馈与计划版本（0.19.0）

在“研究任务”中输入目标、选定论文，先生成计划再运行。规则规划不需要模型；模型建议最多一次规划请求。手动选择输出时直接采用所选工具，不再额外请求模型规划。规则能识别的必要输出与维度会保留，明确否定的工具不会被模型建议重新启用；这是一组有限意图规则，尚不覆盖任意自然语言。

## 恢复设置

新任务可选“保留原文并转本地流程”或“停止并等待处理”，自动调整上限为0—3次，默认2次。策略和上限随计划保存；已有任务的预算可以显式调整，恢复策略需在新任务中选择。

| 反馈 | 当前处理 |
|---|---|
| 原文证据已检索，但模型步骤出现已捕获的HTTP/响应错误 | 策略和调整次数允许时，原步骤保留为失败，保存候选原文，插入一个本地替代步骤，并重接后续依赖 |
| 对比或综述工具报告模型降级 | 保留已完成的本地产物；策略允许时记录新计划版本，关闭后续模型调用。对比工具可能已经分别尝试不同论文，不等于全任务最多一次请求 |
| 首次检索缺少已选论文 | 在原来源范围内最多补检索一次，计入调整次数，后续工具依赖补检索结果 |
| 策略要求停止、次数耗尽、未知工具错误或来源失效 | 停止后续执行，保留检查点；不伪装为已恢复 |
| 工具次数、活动时间或模型预算不足 | 保留产物并按现有预算规则停下或降级；增加预算需要用户显式操作 |

本地替代复用失败前的候选证据，重新检查论文、解析版本、页码、原文与坐标。不重发原失败模型请求，不扩充论文、联网权限或预算。失败尝试与替代步骤各计一次工具调用，所以默认五步计划在恢复后可能处理六步。暂停、取消和预算检查在步骤边界生效，不保证立即打断正在执行的工具。

## 查看结果与历史

“研究任务历史”可打开已保存任务。“计划版本”记录初始步骤、变更原因、依赖与是否关闭后续模型。原失败步骤显示“原尝试失败 · 已转本地替代”，其“查看本地替代结果”按钮进入恢复产物。进度称为“已处理步骤”，没有把失败原尝试改成模型成功。

候选证据仍可点击“PDF第N页”回到原版本原位置。导出任务包包含`task.json`、`plan-history.json`、轨迹、对比、图谱、写作与绘图产物；计划和失败不会只留在页面内存中。旧任务不会自动补写不存在的计划历史；没有新恢复策略的旧任务沿用停止处理，不自动升级为可恢复任务。

任务显示“步骤完成 · 有待核验项”表示已执行当前受控工具链。原文候选、比较短语、综述与写作框架仍须核对，不能解释为科研问题已正确回答。

## 本机可直接查看的演练

历史中保留首轮记录，最新三条2026-10-29记录对应最终v2快照：

- `【本地闭环验收】比较所选论文训练硬件…`：DistilBERT v4与CLIP v1，原文证据→对比→图谱→写作框架→流程图，五步本地执行。
- `【模拟故障演练】比较所选论文训练硬件…`：在独立验证进程中注入一次模拟超时，原失败记录保留，五个本地步骤完成，计划v1→v2。
- `【模拟故障+漏检演练】比较所选论文训练硬件…`：额外注入首轮只返回一篇论文的漏检，恢复后补检索实际返回缺失的CLIP原文，计划v1→v2→v3，七步处理完成。

模拟记录有醒目标识，**不代表真实服务商故障或实际账单**。本轮外部模型请求为0；模拟任务的“执行模型请求1、输出预留1600、用量未报告1”是逻辑预算演练，没有实际发送HTTP请求。正常任务模型请求为0。

可复跑脚本为`scripts/verify_workflow_feedback.py`，参数是`--freeze`、`--workspace`和新的`--output`目录。它核对代码与原文快照，在指定数据库中追加三条任务及关联产物，并拒绝覆盖已有输出；建议使用数据库与所选PDF副本。脚本不启动应用生命周期，不恢复其他任务或开启订阅。原始输出与ZIP保存在[本轮记录](../output/stage23/local_demo_v2/summary.json)。
