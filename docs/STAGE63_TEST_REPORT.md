# 组件存在性小问与否定证据

日期：2026-11-14。本轮完善作品功能；展示发布事项不计入产品未完成条件。

## 问题与实现

上一轮 BERT/Transformer 比较虽然返回整体架构，却没有直接回答“是否都包含用于生成的解码器”，覆盖记录也没有该小问。现在“是否包含/使用/保留”“有无组件”和对应英语问法单独生成组件存在性字段，逐篇保留覆盖状态。此处仍是有限问法识别，不是任意复杂问题的自动分解。

有直接存在证据时返回 present；明确否定时返回 absent，且必须带上同篇已引用证据中的否定原文摘录。摘录校验只允许空白折叠，拒绝改写、凭空摘录和缺少判断的回答。原文没提到某组件时返回 missing，不能把编码器描述自动推成“删除解码器”。判断与摘录保存在审核记录中。

“未提及不等于移除了”是回答约束，不再误识别成额外的架构部件变化请求。原有数字检查、同篇来源检查、证据上限、模型调用上限和无模型只展示原文的行为保留。

## 官方论文实测

共 4 次真实请求，每次沿用 1600 输出 token 上限，不向模型发送预期事实。首次输出、中间失败和最终输出均保留在 output/stage63。

1. BERT/Transformer：修复后以及最终版本均单独覆盖组件判断。Transformer 有编码器和用于生成的解码器；BERT 当前证据描述双向编码器，组件判断明确列为证据不足，不凭未提及作否定。
2. DistilBERT：首次模型漏填判断与摘录，还在额外架构字段中改写数字，均被拦截。修复格式提示和约束子句识别后，明确回答 token-type embeddings 与 pooler 被移除，附第 2 页原句 “The token-type embeddings and the pooler are removed …”。最终无拒绝行。
3. 浏览器恢复 DistilBERT 已保存答案，点击引用后跳至第 2 页并高亮原段，无新增模型请求。
4. 28 道既有检索回归：33/33 预期证据组，168/168 有效锚点，零模型调用。

## 保留边界

否定摘录的字面存在和否定词检查不能自动证明所有语义关系；与所问组件、模型、阶段是否对应仍依赖生成质量和原文核对，因此 semantic_verified 保持 false。多个不同组件目前共用一个存在性字段，尚未实现任意数量组件的逐项结构化拆分。开发题结果不等于总体质量分数，M2-QUALITY 不据此整体改为通过。

完整回归 820 项通过（160.31 秒，1 项已有 Starlette/httpx 弃用提示）。随后补充模型返回错误类型判断时的防护和两个反例，最终字段/查询保持检查 53 项通过。自动化检查结果保存在 output/stage63/checks.json。
