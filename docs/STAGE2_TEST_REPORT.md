ScholarTrace 第二阶段测试记录

记录日期：2026 年 10 月 27 日。版本：0.2.0。范围：扫描 OCR、结构化表格候选、解析历史和本地混合检索。本报告不表示六模块已全部完成。

**1．运行环境。** 独立 `.venv312/`，Python 3.12.14；RapidOCR 3.10.0、ONNX Runtime 1.22.1、FastEmbed 0.9.1、PyMuPDF 1.28.2。原 Anaconda Python 3.11 的 DLL 初始化失败，未用于本轮 OCR。原环境和阶段一数据库备份继续保留。

OCR 权重来自固定版本 RapidOCR wheel，本地准备时检查 SHA256 和三组 CPU 会话；语义模型为 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` 的发布者 ONNX 版本。模型准备是显式步骤，正常上传/健康检查/问答不下载模型，论文未发送到模型下载服务。

**2．自动化回归与构建。** 最终全量 49 项测试通过，执行命令为 `.venv312/Scripts/python.exe -X utf8 -m pytest -q`。有一条 Starlette/httpx 的弃用提示，无失败。

TypeScript 检查和 Vite 生产构建通过。前端已加入重新解析弹窗、OCR来源与识别分数、可复制行覆盖层、HTML表格、历史解析选择和实际检索模式标记。本轮浏览器控制工具两次未能启动，因此没有声称新增界面已通过浏览器交互验收，也没有复用旧截图冒充本轮结果。

自动化OCR接口/坐标测试使用明确的自建数据及注入引擎；下列官方扫描件记录是另行执行真实 RapidOCR 的结果，两者分别解释。

**3．官方扫描版真实运行。** `data/stage2-official-report.json` 保存 `scripts/verify_stage2.py` 的本机 HTTP 实测。

15页状态达标只证明每页产生可用识别文本，未进行逐字人工标注，不能转换成OCR准确率。数字、希腊字母、上下标和公式仍可能识错；界面使用“识别分数”并说明其不等于事实正确率。未将文字识别当作LaTeX恢复或扫描表格结构化。

**4．官方原生表格。** 对 1706.03762v7.pdf 重新解析，最终保留第9、10页的2个表格候选；其余正文和旧run继续保留。注意力图的4个假网格已用联合稀疏度、弱表头、碎字符等信号过滤，过滤未采用硬列数上限，40列真表有保护测试。

第10页候选保留 `Parser / Training / WSJ 23 F1` 三列，可用于原文表格检索。第9页多层表头仍存在列合并，不能视为已完整还原；无框表格和显式clip的text策略也可能拆列。所有结果保留原始cells、null/空值、源坐标、算法与 `verification_status=unverified`。

`data/table_report.json` 记录按页/限定区域对照和过滤原因；源PDF未修改。

**5．本地混合检索。** 实际路径为 BM25 + 384维多语言ONNX向量 + RRF。向量检索使用模型tokenizer划分120-token窗口，保留重叠，避免128-token模型截掉长段落尾部。证据仍引用完整原文块，包含parse_run_id、block_id和bbox。

缓存键绑定文献、解析记录、内容块、文本片段和已校验模型指纹。删除操作和缓存写入复查提供补偿清理；重解析不复用新旧run的错误向量。大文献缺失向量超过请求预算时明确使用BM25，允许CLI预索引，不把部分语义索引包装成全书语义搜索。

`scripts/evaluate_semantic.py` 的3个开发案例中，融合检索均在前6条找到目标片段；纯BM25在中文英德翻译分数问题中无命中，融合检索命中。案例经过开发调试，含领域词扩展，**不是独立留出评测，不报告泛化准确率或提升百分比**。详细结果保存在 `data/semantic-eval-report.json`。

本轮没有配置外部LLM，返回 `evidence_only`；有真实检索证据不等于已经生成和验证科研答案。Rerank、Claim语义支持核验、多文事实矩阵和正式人工评测仍待实现。

最终重启0.2.0后再次通过真实HTTP检查：15页扫描结果均为ocr_ready；硬件问题返回6条OCR证据，实际模式为bm25_dense_rrf，全部证据绑定当前解析记录。摘要保存于 `data/stage2-current-smoke.json`。
