# 全文翻译与研究任务等待

适用0.24.0。[实际结果与失败记录](STAGE28_TEST_REPORT.md)。全文计划绑定一个PDF文件哈希、确切ParseRun和内容块清单，不因后来重新解析而切换来源。

## 从阅读器使用

1. 打开论文，进入“中英对照”。选择中文或English，按需填写术语映射，例如`Transfer Learning=迁移学习`。
2. 选择本页、选中段落、全文或页范围。规划只检查原文和缓存，不请求生成模型。先核对页数、无解析内容页、块数、原样保留数和预计新请求数。
3. 确认本批权限与预算。默认不允许模型，可先“仅使用缓存执行本批”；遇到缓存缺失会暂停，不会悄悄联网。允许模型时明确勾选并填写本批请求、输出预留、处理块数与活动时间上限。
4. 每批最多20次模型请求、70000输出token预留、1000块、900秒；默认3次、10500、50块、180秒。每次新翻译先预留3500输出token。额度不够时在HTTP前停止。实际usage与预留分开显示，预留不是账单或报价。
5. 一批结束后按需明确继续。暂停/取消在单块边界生效，正在进行的HTTP不会瞬间撤回。失败不自动重试，重试需新一批许可；重启后保留检查点并暂停，不自动恢复付费请求。
6. 翻译以原页分组；“原文”回到该版本PDF块位置。可展开原文段落；左侧PDF保留原版式。HTML、MD和ZIP均可导出部分结果，其中未译、失败、原样保留和未支持内容有明确标记。

参考文献跨度、图、表、公式、代码和纯数字/标识等保留原文对象，不计作译文。超过单块支持上限的内容记为未支持，不截短后假称完成。无解析内容的页面不等于已确认的空白页。计划上限20000块、500万字符；短文的“所选范围已处理”只表示清单状态，不表示学术含义已验收。

## 放进研究任务

在“研究任务”中选择翻译输出，将“任务翻译范围方式”改成全文或页范围，再指定论文与术语。生成计划会展示整个范围的缓存/请求估算。任务执行到全文翻译会暂停；在该步骤的独立面板确认每批预算。该面板固定原计划，不允许另建计划来替换等待对象。

全文计划完成后，点击任务上方“继续未完成步骤”，后续写作/流程图等再运行。编排自身的模型请求与全文翻译批次分别统计：上方编排0次不代表全文翻译没有请求。全文批次的许可和额度也不会从编排许可中静默继承。任务ZIP包含`translations/document-plan.zip`；写作框架仍需实施研究与核对，不能当真实实验结果。

## 校订与来源记录

已生成或缓存的译文可打开“校订译文（保留原候选）”。填写译文和修改理由后保存；数字、公式、标识、单位和术语保护检查仍执行。记录绑定源块摘要，包含版本、理由、操作者类型与时间。原始模型候选和全局缓存不覆盖，其他缓存重放不会自动继承某个计划的校订。

导出时采用校订候选并明确标记“未独立核验”；JSON仍保留原候选与修改历史。通过数字检查或保存校订都不会自动得到语义正确结论。实际发现过`term`误译为“学期”，见本轮报告。

旧版段落翻译记录继续支持读取/导出。选区与1—4段任务用法见[原说明](WORKFLOW_TRANSLATION.md)。全文API为`/api/document-translations`：POST建计划、GET状态/按页、POST`/{id}/control`控制、POST`/{id}/edits`校订、GET`/{id}/export`导出；变更需`expected_revision`，冲突先重新读取。具体字段以应用OpenAPI为准。
